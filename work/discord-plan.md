# Discord-автоматизация G4Z CUP — план

Статус: черновик, согласованы требования, доступов ещё нет.
Область: автоматическое создание ролей и голосовых каналов команд, выдача ролей
капитанам и участникам, привязка Discord к аккаунту игрока.

## 1. Требования (зафиксировано)

1. **Голосовой канал команды не закрытый.** Канал видят все участники Discord-сервера,
   но заходить в него могут только игроки этой команды.
2. **Роль «Капитан».** Глобальная серверная роль, которая позволяет заходить во **все**
   голосовые каналы команд. Капитан команды получает эту роль.
3. **Видимость.** Созданную команду (роль и канал) видят все игроки сервера.
4. **Вход.** Возможность подключиться к каналу есть только у участников команды
   и у роли «Капитан»; `@everyone` видит канал, но не может в него зайти.
5. Капитан получает **и** роль своей команды, **и** роль «Капитан».

### Что это значит в правах Discord

Биты прав: `VIEW_CHANNEL = 1 << 10` (1024), `CONNECT = 1 << 20` (1048576),
`SPEAK = 1 << 21` (2097152).

| Кто                         | Видит канал | Может зайти          | Может говорить |
| --------------------------- | ----------- | -------------------- | -------------- |
| `@everyone`                 | да          | **нет**              | —              |
| Роль команды `@team-<slug>` | да          | да (только свой)     | да             |
| Роль «Капитан»              | да          | да (**любой** канал) | да             |
| Бот                         | да          | да                   | —              |

Переопределения на каждом канале команды:

```json
[
  { "id": "@everyone", "type": 0, "allow": "1024", "deny": "1048576" },
  { "id": "<team-role>", "type": 0, "allow": "1048576|2097152" },
  { "id": "<captain-role>", "type": 0, "allow": "1048576|2097152" }
]
```

Роли «Капитан» достаточно `VIEW_CHANNEL + CONNECT` на каждом канале; запрет
`@everyone` на `CONNECT` её не касается, потому что разрешения ролей складываются.

## 2. Юзер-стори

**Капитан**

- «Я создаю команду на сайте и сразу получаю в Discord роль команды, роль „Капитан“ и
  голосовой канал, который видят все, но зайти могут только мои.»
- «Я вижу в кабинете, кто из состава привязал Discord, а кто нет, и могу попросить.»
- «Я закрываю команду — канал уезжает в архив, заходить в него больше нельзя.»

**Игрок**

- «Я принимаю приглашение в команду, один раз разрешаю добавить себя на сервер и
  сразу вижу войс своей команды и могу в него зайти.»
- «Чужие командные каналы я вижу, но зайти в них не могу — это нормально.»
- «Я ухожу из команды и теряю доступ к её каналу, не выходя из Discord.»

**Организатор**

- «Я вижу, у какой команды сломался Discord, и перезапускаю синхронизацию кнопкой.»
- «Я могу зайти в канал любой команды со своей ролью „Капитан“ и позвать людей в войс.»

**Зритель**

- «Я вижу на сервере каналы всех команд, но зайти могу только в свой, если я игрок.»

## 3. Модель данных (миграция `0018_discord.sql`)

`player_profiles`:

| Колонка                    | Тип                   | Назначение                      |
| -------------------------- | --------------------- | ------------------------------- |
| `discord_id`               | text unique           | ID пользователя Discord         |
| `discord_username`         | text                  | для отображения капитану        |
| `discord_linked_at`        | timestamptz           | когда привязал                  |
| `discord_token_enc`        | text                  | OAuth access token, AES-256-GCM |
| `discord_refresh_enc`      | text                  | refresh token, AES-256-GCM      |
| `discord_token_expires_at` | timestamptz           | срок access token               |
| `discord_in_guild`         | boolean default false | подтверждённое членство         |

`community_teams`:

| Колонка                    | Тип         | Назначение                       |
| -------------------------- | ----------- | -------------------------------- |
| `discord_role_id`          | text        | роль команды                     |
| `discord_voice_channel_id` | text        | голосовой канал                  |
| `discord_category_id`      | text        | категория канала                 |
| `discord_synced_at`        | timestamptz | последняя успешная синхронизация |

Служебные:

- `discord_jobs` — очередь идемпотентных задач (`kind`, `subject_id`, `attempts`,
  `next_at`, `last_error`), чтобы 429/5xx не терялись;
- `discord_settings` (одна строка) — id роли «Капитан», категории, сервера; чтобы
  не раскидывать конфиг по env, но env остаётся источником истины.

Публичные проекции (`public_community_team`, `match_details`, `standings`) **не**
содержат Discord-полей. RLS: приватные таблицы уже закрыты; `discord_*` в
`player_profiles` не выдавать колоночными грантами.

## 4. Привязка Discord (OAuth2 + `guilds.join`)

1. В профиле (`/me/profile`) — блок «Discord» и кнопка «Привязать Discord».
2. `GET /auth/discord/start` → подписанный `state` (как `g4z_auth_flow`),
   redirect на `https://discord.com/oauth2/authorize`
   (`scope=identify guilds.join`).
3. `GET /auth/discord/callback` → проверка `state`, обмен `code` на токены,
   `GET /users/@me`, сохранение `discord_id`, шифрование токенов.
4. Сразу `PUT /guilds/{guild}/members/{discord_id}` с `{ access_token }` — добавление
   на сервер по согласию. Успех → `discord_in_guild = true`.
5. Кнопка «Отвязать» — удаляем токены, роли снимаются при следующем синке.

Без привязки человек остаётся полноценным игроком на сайте: Discord — не блокирует
ни регистрацию, ни команду, ни заявку.

## 5. Провижининг

### Создание команды (`team_create`)

1. Бот получает/создаёт роль «Капитан» (один раз, по имени).
2. Создаёт роль команды `team-<slug>` (цвет, `mentionable: false`, `hoist: false`).
3. Создаёт голосовой канал `name = <team name>` в категории «Команды»
   (`type: 2`, `parent_id`) с переопределениями из раздела 1.
4. Капитану: при необходимости добавляет на сервер, выдаёт роль команды и «Капитан».
5. Сохраняет `role_id`, `channel_id`, `category_id`, `synced_at`.

### Вступление игрока (`invite_accept`, `community_link_accept`, `admin_member`)

1. Нет `discord_id` → статус «ждём привязку», сайт продолжает работать.
2. Есть, но не на сервере → `guilds.join` с его токеном (refresh при истечении).
3. Выдать роль команды.

### Выход/исключение (`member_leave`, `member_remove`, `community_leave`, `community_remove`)

Снять роль команды; если это капитан — снять и «Капитан», назначить нового капитана
и выдать роль ему.

### Смена капитана (`captain_accept`, `captain_direct`, `second_remove`)

Новый главный капитан получает роль «Капитан»; прежний — теряет.

### Закрытие команды (`team_archive`)

1. Канал переносится в категорию «Архив» (создаётся при первом архивировании).
2. Снимаются роли команды у всех; роль «Капитан» остаётся только если человек
   капитан другой активной команды.
3. Канал остаётся видимым, но зайти в него нельзя (deny `CONNECT` всем, включая
   «Капитан»).

`team_restore` возвращает канал в «Команды» и роли по текущему составу.

## 6. API-вызовы (кратко)

| Действие           | Метод                                                                |
| ------------------ | -------------------------------------------------------------------- |
| Роль               | `POST /guilds/{guild}/roles`                                         |
| Канал              | `POST /guilds/{guild}/channels` (`type: 2`, `type: 4` для категории) |
| Переместить канал  | `PATCH /channels/{id}` (`parent_id`)                                 |
| Удалить канал/роль | `DELETE /channels/{id}`, `DELETE /guilds/{guild}/roles/{id}`         |
| Добавить на сервер | `PUT /guilds/{guild}/members/{user}` c `access_token`                |
| Выдать/снять роль  | `PUT`/`DELETE /guilds/{guild}/members/{user}/roles/{role}`           |
| OAuth              | `POST /api/oauth2/token`, `GET /users/@me`                           |

## 7. Надёжность и безопасность

- Discord-вызовы **после** коммита транзакции и вне ответа пользователю (`after()`
  из `next/server` или Edge Function по вебхуку).
- Ошибки не ломают действие на сайте: `audit_log` + `discord_jobs` с ретраями
  (экспоненциальная задержка, уважение `retry_after` при 429).
- Идемпотентность: перед созданием — проверка сохранённых id и поиск по имени.
- Секреты только на сервере (`import "server-only"`), токены шифруются,
  `state` подписан, `guilds.join` — только для своего сервера.
- Бот: `Manage Roles`, `Manage Channels`, `View Channels`; его роль выше ролей команд.
- Санитайзинг имён (лимиты Discord), запрет `@everyone`, никакого Administrator.

## 8. Роадмап

1. **M1 — каркас:** миграция `0018`, `lib/discord/client.ts` (fetch, 429, таймауты),
   `lib/discord/provision.ts`, аудит; всё на моках.
2. **M2 — привязка:** OAuth-роуты, блок в профиле, шифрование токенов.
3. **M3 — создание команды:** роль команды, «Капитан», канал с правами, выдача
   капитану; блок статуса в кабинете команды.
4. **M4 — участники:** выдача/снятие ролей при вступлении, выходе, смене капитана.
5. **M5 — архив** и кнопка «Пересинхронизировать» в админке.
6. **M6 — тесты:** юнит с моком fetch (биты прав, 429, ретраи), SQL-ассерты,
   e2e с мок-Discord; один реальный smoke на тестовом сервере.

## 9. Что нужно от заказчика

- Приложение Discord: `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_BOT_TOKEN`.
- Сервер и категория: `DISCORD_GUILD_ID`, `DISCORD_TEAMS_CATEGORY_ID`,
  категория «Архив» (`DISCORD_ARCHIVE_CATEGORY_ID`).
- Redirect URL: `http://localhost:3000/auth/discord/callback`,
  `https://g4z-cup.ru/auth/discord/callback`.
- Бот на сервере с правами выше ролей команд.
- Тестовый сервер (или разрешение создать/удалить тестовые роль и канал на основном).

## 10. Открытые вопросы

1. Второй капитан получает роль «Капитан» или только главный?
2. Нужен ли текстовый канал команды кроме голосового?
3. Показывать ли в кабинете команды ссылку на канал (`discord://`) или только статус?
4. Что делать с капитаном, который не привязал Discord: только напоминание или
   ограничение на создание команды (сейчас — напоминание, ничего не блокируем)?
5. Нужна ли роль «Организатор» помимо «Капитан» (сейчас организатор может входить
   через роль «Капитан», если он капитан; иначе — отдельная роль).
